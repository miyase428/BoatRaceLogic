## 3. point-in-time問題の原因

- 旧監査は `boat_race.exhibition_avg_6m` に保存されている現在の場平均を1件取得し、2023～2026年の全レースへ共通適用していた。
- この平均から `ex_score` を作り、さらに `final_2nd_score`、`second_rank`、`gap_to_top` などへ波及していた。
- したがって展示後MLの一部特徴量に、対象レース時点では確定していない後日集計値が入る時間整合性問題があった。

## 4. 修正方法

- `exhibition_live` から同場の展示タイムを取得。
- race_code・player_idに複数行がある場合は最新行を1件採用。
- 対象日 `D` の平均は `D-183日` 以上、`D` 未満のデータだけで算出。
- 対象日当日は、早いレースも含めて一切平均へ入れない。
- 日付ごとの合計・件数をdequeで保持し、日付×場単位で再利用。
- 学習・VALID・TESTすべて同一ルール。
- 期間冒頭で過去平均を作れないレースは現在値で補わず除外。

使用レース数:
